SOC Detection Lab

Simulate it, detect it, investigate it, write it up

A home SOC on a real Windows endpoint: Sysmon and the Wazuh agent on the laptop, Wazuh in Docker, and a PowerShell script that runs harmless versions of five attacker techniques and cleans up after itself. Every technique has a matching Sigma rule, Wazuh rule and Splunk search, and tests keep the three in sync.

The Splunk searches are generated from the Sigma rules, and a test fails if anyone edits one format without the other. The Wazuh patterns are tested against the exact events the simulations produce, and against ordinary events they must ignore.

[02] ~/why

Why a lab, not just a model

My other security projects score data. A SOC analyst’s day is different: an alert fires, and you have to work out what happened on a real machine, how far it went and what to do.

This lab practises exactly that loop on my own laptop, with real Sysmon telemetry and a real SIEM, and each investigation ends in a written incident report.

HONEST LIMITS

Incident reports are written from my own lab runs as I complete them; the repository starts with the template, not invented results.

Wazuh rule group names can differ between versions; the setup guide shows how to verify each rule with wazuh-logtest.
